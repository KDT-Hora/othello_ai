# 3D オセロ（Cube Othello） - 最終仕様書

## 1. ゲーム概要

**8×8×8 の立方体盤面**上で、黒石と白石が対戦するオセロゲーム。  
従来のオセロのルールを立体化し、「6 つの方向で挟み込み判定」「上下左右前後から手番交代」など、3D ならではの戦略性を備えています。

---

## 2. ゲーム環境（盤面）

### 2.1 盤面の形状
- **8×8×8 の立方体**（合計 512 マス）
- 各マスは `(x, y, z)` の 3 つの座標で表す：
  - `x`: 左→右（0〜7）
  - `y`: 上→下（0〜7）
  - `z`: 前→後（0〜7）

### 2.2 初期配置

ゲーム開始時、**立方体の真ん中部分（4×4×4 の領域の中心部）**に石を配置する：

- **黒石**: `(3,3,3), (3,3,4), (3,4,3), (3,4,4)`
- **白石**: `(4,3,3), (4,3,4), (4,4,3), (4,4,4)`

これにより、黒と白が隣り合うように配置され、ゲーム開始時点で両プレイヤーが挟み込むことができる局面が生まれる。

> 補足：真ん中の「2×2×2」を厳密に解釈するなら `(3,3,3),(3,3,4),(3,4,3),(3,4,4),(4,3,3),(4,3,4),(4,4,3),(4,4,4)` の 8 マスのみとすることも可能だが、ここでは「隣り合うように配置」という要件を満たしつつ、ゲームのバランスを考慮して **各層（x,y,z）ごとに 2×2 マス**ずつ配置する形とした。

### 2.3 空マスの埋め方
ゲーム開始後、プレイヤーは空きマスに石を置いて挟み込みを行い、相手の石をひっくり返すことができる。

---

## 3. ゲームルール

### 3.1 基本ルール（従来のオセロ）

- プレイヤーは自分の番のときに**空いているマスに自分の色の石を置く**。
- 自分の石を置いたマスの周囲から、相手の色の石が挟まれたり、同じ色の石が挟まったりした場合、それらの石は自分の色へとひっくり返る。
- **6 方向（＋x, −x, ＋y, −y, ＋z, −z）すべてで**挟み込みを判定する。

### 3.2 挟み込み判定の仕組み

黒石が `(x,y,z)` に置かれた場合、以下の条件を満たす相手の色 `C` の石が存在するかチェック：

```
  ←(−x)→     (−z)← →(+x)→     (+z)→
      ↑            ↓
   −y        ＋y
```

それぞれの方向について、そのマスの隣接したマスから始めて、相手の色の石が連続しているかどうかを確認し、**挟んだ先頭の石の反対側に自分の色があるか**を確認する。

- **6 方向すべてで挟み込みがあれば、ひっくり返す枚数はそれらの合計となる**。
- **斜め方向（体対角線）での挟み込みは考慮しない**（Q4 の要件より）。

### 3.3 手番交代のルール

従来のオセロと同様、「両端から開く」ルールの立体版を適用する：

1. **上層（y=0, y=7）と下層（y=0, y=7）の両端**について、それぞれの方向で石が置けるかどうかを確認。
2. **左側面（x=0, x=7）、右側面（x=0, x=7）、前面（z=0, z=7）、後面（z=0, z=7）**についても同様。

つまり、「**6 つの面のそれぞれにおいて、石が置ける方向があるか**」を確認し、どちらかのプレイヤーが「すべての面で置ける手がない」場合のみゲーム終了とする。

> 補足：従来のオセロでは「上層と下層（y=0,y=7）から開く」というルールだが、ここでは立方体の各面すべてから開くとしており、「どの面からも開ける」戦略が重要になる。

### 3.4 ゲーム終了条件

以下のいずれかを満たした時点でゲームを終了する：
- **盤面のすべてのマスが埋まった**。
- **どちらかのプレイヤーが置ける手がない**（パス）。

勝敗は、**ゲーム終了時の石数の多い方が勝ち**とする。

## 4. エフェクト・ターン（3D 版）

> 従来のオセロに戻すという要件から、エフェクト能力を廃止する。
> 
> ただし、以下の「3D 特有の戦略的要素」を追加する：

### 4.1 ターン制限ルール

- **黒石・白石の石数の差が±16 に達した時点でゲーム終了**（引き分け判定）。
- または、「盤面が埋まった」時点でゲーム終了。

> このルールにより、ゲーム後半に「盤面を埋め尽くすかどうか」という戦略が重要になる。

### 4.2 3D オセロの勝敗判定

ゲーム終了時に以下のスコアで勝敗が決まる：
- **黒石の個数 > 白石の個数** → 黒（先攻）の勝ち
- **白石の個数 > 黒石の個数** → 白（後手）の勝ち
- **同点の場合** → ドロー

## 5. AI プレイヤー

簡易的な AI を実装する。

### 5.1 AI の戦略

- **評価関数**: `黒石数 − 白石数 + α × （挟み込める枚数の期待値）`
- **探索深さ**: 深さ 2〜3 のミニマックス（枝刈りあり）
- **ランダム性**: 同点の局面ではランダムに手を選ぶ

> 簡易 AI なので、人間プレイヤーには勝てない程度の性能とする。

## 6. GUI / UI デザイン

### 6.1 表示方法：等角投影（Isometric Projection）

- **tkinter Canvas** を使用し、立方体を「斜め上から見た視点」で描画する。
- **各マスは小さな四角形（または円形で）**、3D の奥行きを表現するために色や影をつける。
  - 前面の面：明るい灰色の枠
  - 右面の面：やや暗いグレーの枠
  - 後面の面：さらに暗いグレーの枠

### 6.2 マスの表示

- **黒石**: 濃いグレーの円形（または四角形）
- **白石**: 白〜薄灰色のグラデーション
- **空マス**: グレーの背景色（`#3a3a4e` など）
- **挟み込める手**: マスの上に小さな「+」マークを表示

### 6.3 エフェクト・演出

- **石がひっくり返るアニメーション**：Canvas の `canvas.coords()` を更新して滑らかに移動させる。
- **ゲーム終了時の勝敗表示**：大きな文字で勝利メッセージを表示。
- **ターン表示**：「黒の番」または「白の番」というテキストを表示。

## 7. システムアーキテクチャ

### 7.1 全体構成

```
┌─────────────────────────────────────┐
│           GUI Layer (tkinter)        │
│   ┌──────────────┬──────────────────┐│
│   │  Canvas      │  Control Panel   ││
│   │  (盤面表示)  │  (操作ボタン等)  ││
│   └──────────────┴──────────────────┘│
│         ┌───────────────────┐        │
│         │ Game Engine       │        │
│         │   (CubeOthello)   │        │
│         │                   │        │
│         └───────────────────┘        │
└──────────────┬────────────────────────┘
               │
    ┌──────────┼──────────┐
    ▼           ▼          ▼
┌──────────┐  ┌─────────┐  ┌──────────┐
│ CubeBoard │  │ Effect  │  │ AI Player│
│ (盤面管理)│  │ Manager │  │ (簡易AI) │
└──────────┘  └─────────┘  └──────────┘
```

### 7.2 コンポーネント詳細

- **CubeBoard**: 8×8×8 の盤面データ、初期配置、挟み込み判定、石の置き替えなど
- **EffectManager**: ターン管理、ゲーム終了条件の評価
- **AIPlayer**: 簡易ミニマックス AI（深さ制限付き）
- **GUIController**: tkinter Canvas で盤面を描画・更新
