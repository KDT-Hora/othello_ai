# Cube Othello — ゲーム仕様の最終版

## 0. はじめに

Cube Othello（キューブ・オセロ）は、従来の 2D オセロのルールを踏襲しつつ、盤面形状を「8×8×8 の立方体」に変化させたオセロゲームです。

本仕様書では、Q9（平面表示方式）と Q10（簡易 AI：石数のみ評価）を確定した最終的な設計を定めます。

## 1. ゲームの概要

### 1.1 ゲームジャンル
- オセロ（リバーシ）の拡張版
- 盤面形状：**8×8×8 の立方体**（512 マス）

### 1.2 プレイヤー
- **黒（B / Black）**：先攻
- **白（W / White）**：後手

## 2. 盤面の定義

### 2.1 座標系
| 軸 | 方向           | 範囲   |
|----|----------------|--------|
| x  | 左 → 右        | 0〜7   |
| y  | 上 → 下        | 0〜7   |
| z  | 前 → 後（奥行き）| 0〜7   |

### 2.2 マスの状態
- `.` : 空（置ける手）
- `B` : 黒の石
- `W` : 白の石

### 2.3 初期配置
立方体の「真ん中の部分」の中心部、すなわち `(3,3)〜(4,4)` の範囲内で隣り合うように配置：

| 座標 (x,y,z)                         | 色 |
|--------------------------------------|----|
| (3,3,3), (3,3,4), (3,4,3), (3,4,4)  | B  |
| (4,3,3), (4,3,4), (4,4,3), (4,4,4)  | W  |

この配置により、両プレイヤーから挟み込みが可能になります。

## 3. ゲームのルール

### 3.1 基本ターン
- **黒が先攻**し、置ける手がない場合はパス。
- 各ターンでは、次の条件を満たすマスを選択：
  - 黒の石を置いて、相手の石を挟むことができること
- 挟まれた相手の石はすべてひっくり返されます。

### 3.2 挟み込み判定（6 方向のみ）
**＋x, −x, ＋y, −y, ＋z, −z の各軸に沿って**「相手の石 → 自分の石」というパターンを検出し、挟み込めるかどうかを判定します。斜め方向は考慮しません。

### 3.3 ターン交代（パス）
- 「黒が置ける手がない」または「白が置ける手がない」場合、次のプレイヤーにターンを譲る。
- **双方とも置ける手がない**場合はゲーム終了。

### 3.4 ゲーム終了条件
以下のいずれか成立するとゲームは終了します：
1. 盤面が完全に埋まっている場合
2. どちらかのプレイヤーが置ける手がない場合（パスが発生）

### 3.5 勝敗判定
ゲーム終了時に、**両プレイヤーの石数が多い方**が勝ちます。

## 4. ゲームフロー

```
開始 → 黒の番 → （石を置く / パス）→ ターン交代 → 
        ↓
   ゲーム終了条件を満たすか？ ──Yes──► 勝敗判定 → 終了
        │
      No
        │
        ▼
（白の番へ同様に繰り返す）
```

## 5. AI の仕様（簡易版）

### 5.1 評価関数
- **石数のみ**を考慮する。
- `スコア = (自分の石) − (相手の石)`
- 挟み込み枚数は評価に入れない。

### 5.2 アルゴリズム
- 簡易ミニマックス（深さ制限付き：デフォルト depth=3）
- 枝刈りは行わないが、有効手の数に応じて探索を短縮する。

## 6. GUI の仕様

### 6.1 描画方式 — **平面表示**
等角投影による 2D グリッドで 8×8×8 を表現します：

- x 軸方向の増加は「右下がり」
- y 軸方向の増加は「左上がり」
- z 軸（奥行き）の変化は「明度変化」のみで表現（前面が明るい、後面が暗い）

### 6.2 表示要素
- 立方体の枠線（8 つの面の境界）
- 各マスに黒・白の石（円形で描画）
- 挟み込める手には「+」マークを表示（最大 20 マスまで）
- インフォパネル：スコア、現在のターン、ゲーム終了メッセージ

### 6.3 技術スタック
- **Python 標準ライブラリのみ**を使用。
- `tkinter` を用いた Canvas ベースの GUI。
- 外部依存はなし（numpy はオプション）。

## A. Q9 の回答：GUI の視覚表現方式 — 平面表示（A）

**選定：** A — 平面表示  
- 等角投影による 2D グリッドで 8×8×8 を表現する。
- z 軸の奥行きは明度変化だけで、立体感は「前面と後面の色差」のみで表現。
- 理由：複雑な透視図法よりも直感的に理解しやすく、かつ tkinter の Canvas で容易に実装可能だから。

## B. Q10 の回答：AI の簡易性範囲 — 石数のみ評価（A）

**選定：** A — 極めてシンプルな AI  
- 挟み込み枚数や将来の手数を考慮せず、「現在の盤面の石数差」のみで評価。
- デフォルト探索深さ：3（枝刈りなしの簡易ミニマックス）。
- 理由：「簡易 AI」という要件を満たし、かつ実装がシンプルになるため。
